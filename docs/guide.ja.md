# 自分のゲームで試す

[作例に戻る](../README.ja.md) · [英語のワークフロー全文](../SKILL.md)

1. **遊べる一場面を渡す。** どの画面を開き、どこを押し、何が起きるのかを伝えます。対象端末の大きさと、すでに気に入っているキャラクターや操作も添えます。
2. **参考にする理由を絞る。** 人物が背景からどう浮かぶのか、押した後で視線がどこへ移るのかを選びます。輪郭は静止画で、動きの順番は映像や実機で確かめます。
3. **一つの動作を仕上げる。** 入力と判定を固定し、予備動作から接触、収まりまでを作ります。スマートフォンで最も明るい一瞬と、その後の操作の見つけやすさを確認します。
4. **一局に広げる。** 代表の一場面が決まったら、人物、メニュー、一時停止、結果画面に色や形、素材の扱いを引き継ぎます。
5. **同じ条件で比べる。** 同じ入力を改修前後で記録し、連打、中断、失敗、視差効果の軽減も試します。確認した端末と挙動を記録します。

最初の依頼には、こんな書き方ができます。

> Indie Game Art でこのゲームの配色と光を決めてください。同じ場面で二つの案を描き、スマートフォンの大きさで人物の見つけやすさを比べたいです。選んだ案でキャラクターとボタンの質感を仕上げてください。

## 一枚の絵から決める

場所と時刻、そこで感じてほしい気分を一つ選びます。同じ被写体を二、三枚の小さな絵にして、実際に遊ぶ大きさで視線の行き先、人物を囲む余白、光が残る道具を見比べます。選んだ一枚を人物の輪郭、操作面の素材、環境の動きにも引き継ぎます。採用しなかった一枚と、その理由も残します。[港のカラーキー](../assets/studies/harbor-color-script.webp) · [画づくりの手引き](../references/look-development.md)

一次資料を使うときは、見えたもの・自分の解釈・試作で借りる具体的な手法を分けて記録します。雰囲気を探る絵と実機の画面も区別します。[資料ノート](../references/source-notebook.md)
