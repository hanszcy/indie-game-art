# 自分のゲームで試す

[作例に戻る](../README.ja.md) · [英語のワークフロー全文](../SKILL.md)

1. **遊べる一場面を渡す。** どの画面を開き、どこを押し、何が起きるのかを伝えます。対象端末の大きさと、すでに気に入っているキャラクターや操作も添えます。
2. **参考にする理由を絞る。** 塔と敵の輪郭をどう区別するか、着弾後にどこへ視線を導くかなど、一作品につき一つの問いを決めます。静止画では輪郭を、映像や実機では動きの順番を確認します。
3. **一つの動作を仕上げる。** 地形、入力、攻撃力を固定し、待機から発射、着弾までを作ります。スマホで最初の反応と光の強さを確かめ、次の敵が隠れないかを見ます。
4. **一局に広げる。** 代表的な場面が決まったら、塔の選択、一時停止、遺物、結果画面にも素材や輪郭のルールを適用します。数値や当たり判定はゲーム側に持たせます。
5. **同じ条件で比べる。** 同じ一手を改修前後で記録し、連打、中断、敗北、視差効果の軽減も試します。試した端末と確認できた挙動を明記します。

依頼の例：

> $indie-game-art でスマホの塔の選択を調べて。選択中の塔、建造場所、真鍮が足りない状態を見分けられるようにしたい。まず火花塔で試してから、ほかの二つの塔に広げて。
