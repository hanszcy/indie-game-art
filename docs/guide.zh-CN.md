# 在自己的游戏里使用 Indie Game Art

[回到案例](../README.zh-CN.md) · [完整英文工作流](../SKILL.md)

1. **给一个可玩的瞬间。** 说明从哪个页面进入、点哪里、应该看到什么。附上目标设备尺寸，以及已经认可的角色或规则。
2. **让参考解决一个问题。** 先决定要观察人物怎样从背景中显出来，还是玩家按下按钮后视线应该移到哪里。轮廓可以看静态截图，动作先后要看录像或实机。
3. **先改一个动作。** 保留输入和判定，打磨预备、接触和收尾的姿势。在手机上看清哪一帧最亮，以及反馈结束后下一次操作是否容易辨认。
4. **扩展到整局。** 确认代表场景后，把同一套色彩、轮廓和材质用到角色、菜单、暂停和结算。
5. **用相同条件回看。** 记录改动前后的一次相同操作，再试连续点击、中途暂停、失败和减少动态效果模式。交付时写明检验过的平台。

可以从这个请求开始。

> 用 Indie Game Art 帮我确定这款游戏的用色和光照。给同一场景画两张小稿，在手机尺寸下比较角色是否清楚。根据选定的一张，再打磨角色和按钮的材质。

## 先把画面定下来

先给一个地点和时刻，再说希望玩家在那里感到什么。把同一个主体画成两三张小稿，缩到游玩尺寸，看第一眼落在哪里，人物周围哪块空间显得安静，光最值得留在哪个物件上。用选定稿校准角色轮廓、UI 表面和环境动势；保留一张被舍弃的稿和舍弃理由。[原创港口色稿](../assets/studies/harbor-color-script.webp) · [画风与气氛工作手册](../references/look-development.md)

一手参考可以是一张图、一段视频或美术作者的制作记录。分别写下看到的画面、你对它的解读、试着移植的具体手法。把实际玩法截图和目标气氛稿分开归档。[案例笔记](../references/source-notebook.md)
