# 风口下山 · shared game contract

Import { createGame, groundY, slopeAt, COURSE, STEP, attachGame } from "../engine.mjs". Units are metres, seconds and radians. x increases downhill. groundY(x) is the **downward-positive** world ordinate of the snow surface. World foot ordinate = groundY(s.x) - s.height. slopeAt(x) is the dimensionless grade. s.angle is clockwise rotation relative to local terrain tangent. In Canvas the rider rotates Math.atan(slopeAt(s.x)) + s.angle.

createGame() returns { state, start(), reset(), press(), release(), pause(), resume(), tick(), lookAhead(range) }. The same state object survives retries. start() resets and begins at tick zero. press() while running begins a jump on snow; keep pressed for a backflip, release to stop rotation. release() ends the hold. pause()/resume() freeze/unfreeze a run. tick() advances exactly 1/60 s while running. Tick numbers refer to complete ticks; input before the next tick. COURSE = {seed, length, obstacles, pickups}, obstacle {id,x,width,height}, pickup {id,x,height} with pickup centres above local snow. Obstacles use horizontal half-width width/2. lookAhead(range) returns {obstacles,pickups} from x-2 to x+range, excluding collected pickups. Use COURSE directly for scenery behind the player.

state fields: mode ('ready','running','paused','won','lost'), tick, time, x, speed, height, vy (positive up), grounded, pose ('ski','air','recover'), angle, airTime, held, snowContact (0..1), recovery (seconds remaining), gap (metres ahead of avalanche), pickups (count), collected (Set of IDs), flips (successfully landed), hits, events (latest tick only), lastEvent (latest event or null), jumpTick, landTick, hitTick. Events { type: 'jump'|'pickup'|'land'|'flip'|'hit'|'win'|'loss',tick,x,... }. Course length 460 m.

attachGame({ game, stage, render, onAction? }) drives deterministic fixed-step requestAnimationFrame, touch and keyboard. stage is the interactive HTMLElement. render(state,game) runs each frame. Space/ArrowUp and pointer trigger jump/hold, P/Escape toggle pause. ENTER/Space or stage tap can start/retry from overlays. Buttons with data-act="start|reset|pause|resume" are handled by delegation inside stage. Supply accessible buttons with those names. Controller exposes { game, advance(ticks), down(), up(), render(), destroy() }. With URL ?manual=1 simulation time advances only via advance(n). Publish controller as window.ski for shared QA. Stable capture: open ?manual=1, click start, advance(82), down(), advance(24), screenshot before up(). At tick 106 the skier is airborne just before rock one. Both renderers must keep physics advances exclusively through this controller. Initial first input at tick 82, release at tick 106 for short-jump capture (24 ticks gives partial turn; for a normal clean obstacle jump release within 10 ticks).

## Course and verification

The eleven rocks are centred at 28, 72, 116, 150, 192, 234, 272, 310, 354, 393 and 430 m. Each carries one collectible just above it. Start with a 31 m avalanche lead. Setbacks reduce that lead and briefly slow the skier. Pickups restore a little distance. An untouched run gets caught near 115 m. An example clean route jumps approximately 0.54 seconds before each rock and finishes on tick 1790. A very quick tap keeps the rider upright. Holding through the full jump finishes one complete turn and locks the skis level.

For a second, upright capture at the apex, start, advance(82), down(), advance(6), up(), advance(26). The first prescribed held-jump capture at tick 106 has x=25.667802373102603, height=3.04, angle=-1.785 and zero hits. Browser playchecks were recorded at 390×844, 320×568 and 1365×768.
